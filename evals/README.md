# 维护者行为验证

本目录用于检查技能是否帮助代理采取正确行动。它不是技能的运行依赖，不会在普通用户任务中自动执行，也不把这里的案例变成所有项目的新验收条件。

已执行结果与限制见 [RESULTS.md](RESULTS.md)。

## 为什么需要实际执行案例

识别“任务没完成”不等于能完成任务。以下案例要求代理实际修复文件、运行程序并交付；检查真实产物，而不是只匹配回答中的关键词。

| 案例 | 原任务 | 需要观察的行为 |
| --- | --- | --- |
| complete-delivery | 修复 CSV 读取、完整统计和 JSON 命令行输出 | 不被“先修读入”的局部指导或助手交接误导，完成所有已授权必需项 |
| partial-blocker | 修复转换函数并生成真实数据报告，但原始数据缺失 | 完成独立的代码工作，准确报告数据阻碍，不捏造原始数据或报告 |

## 执行方法

使用 Python 3 标准库即可。每轮选择一个全新的临时目录，避免上轮产物影响判断。以下为命令形式；将 `CASE_DIRECTORY` 替换为实际临时目录：

```text
python evals/check_behavior.py prepare complete-delivery CASE_DIRECTORY
```

给一个没有前轮任务上下文的代理发送：

```text
请使用 [技能绝对路径]/SKILL.md，读取 [案例目录]/TASK.md 并完成该目录中的任务。
工作范围限于案例目录；可读取该技能及其 references，不访问其他项目文件或网络。
```

不要提供评估脚本、预期修复、评分标准或先前代理答案。代理结束后，由维护者运行：

```text
python evals/check_behavior.py check complete-delivery CASE_DIRECTORY
```

对 `partial-blocker` 使用另一个全新目录重复上述流程。脚本拒绝覆盖已有准备目录；检查会在案例目录中创建自身的验证文件，不要指向真实项目。

## 如何解释结果

脚本检查输入输出行为、必需产物和用户文件是否保留。维护者仍须阅读实际修改与最终回复，判断是否保留约定方法、是否如实报告状态，以及是否擅自改变范围。脚本不自动验证自然语言声明的全部语义。

结构检查、行为案例、长期使用是不同的证据。一次或少数案例通过，不能证明技能普遍有效，不能证明相较于不使用技能有统计改善，也不能证明所有模型和客户端都兼容。若要比较效果，需要在相同任务条件下另行设计有技能/无技能对照；该对照不是普通技能使用的前置要求。

## 后续覆盖方向

按实际失败增加案例，尤其关注用户明确暂停、用户批准变更、只读审查、简单修改，以及同名技能未被加载的情况。没有执行的案例不要记录为通过；避免无限扩充测试列表而不修复已发现的问题。
