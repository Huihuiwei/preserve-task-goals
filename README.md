# Preserve Task Goals

**让 AI 代理持续完成用户要求的任务，并用真实证据说明完成情况。**

[English](README.en.md) · [安装教程](docs/installation.md) · [使用示例](docs/examples.md) · [技能正文](SKILL.md)

`preserve-task-goals` 是面向 Codex 的通用 Agent Skill。它针对一种常见问题：代理看起来一直在工作，却逐渐缩小目标、陷入局部细节、换掉原定方法，最后把有限的结果说成整体完成。

它将“保持目标不变”落实为可执行的判断流程：核对用户确认的要求、辨别范围变更、检查功能是否真正参与计算、核验结果来源，并按证据交付。适用于代码开发、研究实验、数据分析、文档交付及跨会话续接。

## 一句话安装

将下面整段复制到 **Codex 的对话框**，不是系统终端：

```text
请使用 $skill-installer 从 https://github.com/Huihuiwei/preserve-task-goals 安装 preserve-task-goals。
技能入口在仓库根目录 SKILL.md，仓库内路径为 .，安装名称为 preserve-task-goals。
请先检查技能内容，再安装到当前 Codex 支持的个人技能目录。
如果已有同名技能，请先比较并保留本地修改，不要直接覆盖。
完成后告诉我实际安装位置和如何调用；不要把仅下载成功说成已确认可用。
```

首次使用：

```text
请使用 $preserve-task-goals，按我们已经确认的目标继续当前任务。
先核对实际进度，然后直接推进未完成的必需内容；不要自行缩小范围。
```

没有 `$skill-installer`、不会用 Git、需要 Windows/macOS/Linux 手动安装？看[新手安装教程](docs/installation.md)。

## 主要解决什么问题

| 问题 | 这个 Skill 要求代理做什么 |
| --- | --- |
| 目标被偷换或缩小 | 回到用户明确确认的目标，保留必需机制、场景与交付 |
| 陷入局部小目标 | 将子任务对应到具体交付或阻碍，解决后返回主线 |
| 擅自扩大研究或工程 | 把额外改进作为建议，不变成原任务前置条件 |
| 用更容易的方法替代原方案 | 区分实现修错和范围变更，后者先取得明确同意 |
| 参数有名字却不起作用 | 检查调用路径、数据流、状态更新和可观察作用 |
| 测试通过但功能仍错误 | 避免自证循环，使用与风险匹配的独立验证 |
| 修改阈值制造通过 | 保留失败，凭依据修正实现或检查，不降低验收 |
| 局部结果冒充完整验证 | 区分证据类型、适用条件和实际覆盖范围 |
| 旧结果证明新代码 | 核对版本、配置、数据及结果来源，重验受影响部分 |
| 不断审查却迟迟不交付 | 满足既定要求且解决相关风险后停止追加检查 |

完整参考：[18 类偏差及处理方法](references/failure-patterns.md)。

## 包含哪些功能

1. **任务基准核对**：区分用户确认、助手建议、待确认事项。
2. **范围变更判断**：允许原范围内自主修错，避免每一步重复请示。
3. **真实实现检查**：检查机制实际作用，不以函数存在代替实现完成。
4. **验证口径保护**：检查能否发现错误，避免改验收标准来迎合结果。
5. **证据追溯**：核对代码、配置、数据、输出与结论的对应关系。
6. **完成状态核验**：区分代码已写、执行成功、局部通过和完整验收。
7. **跨会话续接**：读取相关实际文件核实状态，不盲信交接总结。
8. **偏离后的恢复**：更正错误声明，保留有效工作，返回原任务。
9. **最小记录模板**：复杂任务按需记录要求与证据，简单任务不增加文书负担。
10. **常驻规则配合**：提供可合并到 `AGENTS.md` 的短规则，不自动改写配置。
11. **原任务一致性检查**：分别判断“做的是 A 还是替代任务 B”和“A 是否完整”，不让 B 的通过掩盖任务偏离。
12. **持续完成已授权工作**：有可执行的必需项就继续，不能列出未完成清单后等待用户重复说“继续”；暂停需说明实际阻碍。

## 工作方式

技能按任务需要选择入口，不强制每次走完整流程：

| 当前情况 | 主要动作 | 应得到的结果 |
| --- | --- | --- |
| 开始或恢复任务 | 核对已确认目标和真实进度 | 清楚的下一项必需工作 |
| 遇到实现困难 | 判断修错还是范围变更 | 原范围内继续执行，或明确提出变更 |
| 用户指出跑偏 | 比较原要求、实现与证据 | 修复偏差并更正状态 |
| 准备宣布完成 | 核对必需项和实际验证 | 有证据的完成说明，或具体缺口 |

例如，原要求是“完成三个场景的验证”，当前只跑通一个案例，正确输出应说明已覆盖哪个场景、剩余哪些工作，并继续执行。不能把单个案例重新命名为“完整验证”。

## Skill 与 AGENTS.md 怎么配合

`AGENTS.md` 保存常驻规则；Skill 提供按需执行的方法。安装技能并不保证每轮都会自动调用，关键任务可以显式写 `$preserve-task-goals`。

需要项目长期遵守的简短约束时，将 [templates/AGENTS-snippet.md](templates/AGENTS-snippet.md) 的内容合并到现有 `AGENTS.md`，保留原项目规则。仅安装本技能不会修改你的全局指令或项目配置。

## 如何验证 Skill 本身

区分三种检查：文件结构是否正确、代理是否能识别问题、代理是否实际完成了要求的工作。前两项通过不能替代第三项。

仓库提供两个可复用的执行案例：一个要求完成 CSV 读入、统计与 JSON 输出，另一个要求在真实数据缺失时继续完成独立代码修复。检查脚本核对实际输入输出和产物，维护者再核对最终声明。评估工具只用于维护技能，不会在你的普通任务中自动运行，也不代表对所有任务的正确性保证。

详见[行为验证方法](evals/README.md)。

## 能力边界

这是指令与参考资料组成的技能，没有后台守护进程，也不会自动拦截文件修改或保证模型永不出错。它不替代真实测试、版本管理和人工判断，不授予额外权限。

技能正文使用中文，带有英文触发描述，并要求按用户语言回复。其他兼容 `SKILL.md` 的代理可移植使用；具体安装位置和触发方式需要按对应产品核实。本仓库不宣称已经完成所有代理、模型或平台的兼容性测试。
