# 可直接复制的使用示例

[返回首页](../README.md)

将下面的提示词发给已经安装该技能的 Codex。方括号表示需要填写的任务内容；不需要的字段可以删去。用户已经讲清楚的要求不用重复确认。

## 开始一个多步骤任务

```text
请使用 $preserve-task-goals 完成以下任务：[任务描述]。
必须保留：[已确认的方法、功能、数据或交付]。
完成条件：[明确的验收要求]。
请在这个范围内直接推进，关键完成声明对应实际验证，不把局部案例当作整体完成。
```

预期：代理提取真实要求，推进实现；不把缺少的信息随意补成更高验收门槛。

## 跨会话继续

```text
请使用 $preserve-task-goals 继续当前项目。
先读取与本次任务有关的用户要求、项目记录和实际结果，核对真实进度。
不要只依据上一轮“已经完成”的总结。然后继续完成未完成的必需项。
```

预期：代理检查相关证据，不重复扫描所有文件，也不把自己的交接总结当作用户批准。

## 修复错误且保留原方法

```text
请使用 $preserve-task-goals 修复 [具体错误]。
保留原定算法含义、接口约定和评价口径。
在已有授权内直接修错，验证受影响的行为；如果确实必须改变原方法，先说明影响。
```

预期：代理修正逻辑和直接相关接口，不借修错替换模型或扩大功能。

## 完成研究实验

```text
请使用 $preserve-task-goals，按照已经确认的场景、基线、消融和指标完成实验。
保留负向结果。分别说明数学诊断、合成案例、真实数据实验或实测证据实际覆盖的内容。
不能为了更容易得到正向结果而更换目标或验收条件。
```

预期：代理完成既定矩阵，明确运行版本、配置和统计集合；不增加未批准的研究任务。

## 核查“是否真的完成”

```text
请使用 $preserve-task-goals 检查当前完成声明是否成立。
逐项对应已确认要求、真实实现和已执行验证。暂时不要修改业务代码。
明确指出缺失机制、失效证据、未执行检查和仍然受阻的内容。
```

预期：代理完成审查并给出准确状态。发现缺陷不代表审查工作未完成，也不自动授权全面重构。

## 纠正任务跑偏

```text
请使用 $preserve-task-goals。当前任务可能已经偏离原要求。
请比较原目标、当前实现和验证证据，更正不成立的完成声明。
在原授权范围内修复偏差并继续推进，保留已有有效工作和原始结果。
```

预期：代理指出具体偏差并采取行动，不仅重新写一份计划或重复道歉。

## 文档或报告交付

```text
请使用 $preserve-task-goals 完成 [文档任务]。
保留我指定的章节、信息和格式，不把精简表达变成删减关键内容。
需要渲染或核对的部分按原要求完成；没有执行的检查明确标注。
```

预期：代理按交付范围处理内容与格式，不因代码运行成功就声称版面已验证。

## 测试失败时

```text
请使用 $preserve-task-goals 排查当前验证失败。
先区分实现错误、输入问题、假设不成立和检查本身错误。
不要通过放宽阈值、删除失败项或修改统计集合来制造通过。
修正应有独立依据，并说明影响了哪些既有结论。
```

## 做成了替代任务，且没有做完整

先看下面这个例子，适用于“说好了 A，却做成了 B，而且还没做完”的情况：

```text
请使用 $preserve-task-goals 回到我们已经确认的原任务。
先从我的明确要求中列出必需交付，分别核对当前工作是否对应原任务、是否全部完成。
不要根据你已经做出的产物反过来定义任务，也不要只检查你自己的计划是否完成。
发现偏离时保留有效工作并修正。有已授权、可执行的必需项就继续做，
不要以“剩下这些以后可以继续”结束；确实受阻时说明具体阻碍及最小解除条件。
```

## 简单修改时保持轻量

```text
请使用 $preserve-task-goals，把 [文件] 中的 [明确的小问题] 修正。
按任务规模核对即可，不需要新建计划、证据表或额外测试体系。
```

预期：技能帮助保持范围，不把轻量操作升级成繁重流程。
