# 18 类目标与证据偏差

仅在排查相关问题时使用；这是一份判断参考，不是每次任务必须执行的十八项验收。

| 类型 | 可观察信号 | 对应动作 |
| --- | --- | --- |
| 目标偷换 | 完成了容易交付的替代任务，原问题仍未解决 | 追溯用户原目标，把当前产出映射回必需交付 |
| 范围缩水 | 场景、数据、机制或指标减少，任务仍沿用原名 | 恢复未批准删减的内容，明确局部证据范围 |
| 局部目标绑架 | 长期打磨一个细节，却无法说明对主目标的影响 | 说明具体阻碍；不构成阻碍时返回剩余必需项 |
| 范围膨胀 | 新增认证、复现或基线成为前置条件 | 将未批准扩展移回建议，继续原任务 |
| 方法暗换 | 模型、算法或数据口径已换，名称与声明未变 | 核对授权；未经批准不能当作原方案完成 |
| 形式实现 | 模块和参数存在，但调用或数据流中不起作用 | 检查实际执行路径及机制的可观察作用 |
| 代理指标替代 | 用收敛或低层指标证明最终业务/研究效果 | 回到用户要求的效果与验收证据 |
| 为通过而改检查 | 失败后放宽阈值或移除失败项，无独立依据 | 保留失败，排查实现及检查本身的错误 |
| 自证循环 | 标准答案由被测实现或相同假设产生 | 使用适当的独立答案、推导或机制干预 |
| 证据等级混淆 | 数学诊断被称作实测验证，局部案例被称作完整评估 | 按证据来源与覆盖条件分别报告 |
| 选择性报告 | 只展示有利设置，未交代失败或平均集合 | 报告完整的既定集合及负向结果 |
| 完成状态虚报 | 写代码、启动进程或部分通过被说成整体完成 | 根据当前实现和已执行验证重新标注状态 |
| 文档迁就错误 | 代码偏离后修改原需求，使偏离看似原设计 | 恢复需求基准，修正实现或申请明确变更 |
| 建议变成批准 | 助手自己的计划被用作用户授权 | 返回用户原始要求和明确批准记录 |
| 局部修复失配 | 单个函数修好，上下游单位、接口或统计含义失配 | 核验直接受影响的整体关系 |
| 结果来源混乱 | 新旧代码、配置或数据集合混用 | 标明每项证据来源并重验受影响部分 |
| 难点绕行 | 文档图表不断增加，核心功能留作后续 | 优先实现关键缺项，保持未完成状态可见 |
| 无止境检查 | 已满足要求后不断新增检查与优化 | 以既定验收和实际风险为停止条件 |

不要仅凭措辞给任务贴标签。先检查原要求、实现和证据，再作具体判断。真实的用户变更、合法的探索及准确标注的局部诊断不属于违规缩水。
