# 范围与证据判断示例

把以下示例用于识别问题，不把示例中的测试、模型或交付要求推广为所有任务的必需项。

| 原要求与遇到的情况 | 正确处理 | 不应作出的结论或动作 |
| --- | --- | --- |
| 完成多场景验证，目前只跑通一个合成案例 | 保留原实验矩阵，记录该案例支持的局部性质，继续其余必需验证 | 宣称完整方法已经验证，或把其余场景改为未来工作 |
| 参数已声明，但计算始终使用固定常量 | 检查调用与数据流，修正逻辑，并按机制预期核验影响 | 以参数名和函数存在证明功能已实现 |
| 既定模型难以实现，另一个模型更容易运行 | 在原模型范围内排障；若建议替换，解释影响并等待明确批准 | 直接换模型，再修改论文说明使之看似原定方案 |
| 检查把数学上未定义的指标当作零而失败 | 核对既定指标定义及独立依据，修正错误检查并说明受影响结果 | 为通过任意改数值、删除失败场景，或无说明更改平均集合 |
| 用户要求完整交付，助手发现一个可选认证 | 完成原要求，把认证作为单独建议 | 将认证设为前置条件并阻塞交付 |
| 用户询问“能否换成另一种方法” | 回答可行性与影响；将变更保持为未批准状态 | 把提问或自己的方案当作实施授权 |
| 用户明确要求修正单位错误 | 在已有授权内修复，核验受影响结果并同步说明 | 反复请求相同授权，或借修错改动研究目标 |
| 新代码仍引用旧版本结果 | 判断修改影响范围，保留仍有效的证据，对失效部分重新验证 | 用旧结果证明新实现通过，或无差别重跑所有内容 |
| 指标为负向或收益不显著 | 报告实际结果并约束结论，按既定要求完成剩余分析 | 选择性隐藏、换目标或改验收线以获得正向结果 |
| 用户只要求检查错误并给出报告 | 完成约定检查并如实报告发现 | 因被审对象未通过而声称审查任务本身未完成，或未经要求进行全面重构 |
| 用户明确要求实现并验证，审查已完成 | 继续修复与验证，不能以报告代替实现 | 宣称“分析已完成”就满足原任务 |
| 关键实现满足既定要求后发现可选优化 | 返回剩余必需交付或结束任务 | 无限调优、无限检查或新增更高门槛 |

如具体项目已有明确规则，以当前用户要求及适用项目指令判断；示例不构成变更授权，也不授予外部操作权限。
